# REVIEW.md

List every defect found in the starter `app/main.py` (helpers and endpoints).

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `MongoClient(...)` at module top | The client is not `tz_aware`, so PyMongo returns naive datetimes. Python can't tell whether they are UTC or IST, and mixing naive and aware datetimes crashes. | Subtracting a stored `punch_in` from an aware IST time raises `TypeError: can't subtract offset-naive and offset-aware datetimes`. | Set `tz_aware=True` on the client and normalise every instant through a `to_utc()` helper. |
| 2 | `compute_late_minutes` | (a) Builds the shift start from the punch-in's own (UTC/naive) date and hour instead of the IST shift start. (b) Floors to whole minutes before the grace check, so 10:00.x is treated as 10 and ignored. (c) Never truncates seconds (R1). (d) No overnight handling. | Shift 09:30, punch-in 09:40:01 returns 0 instead of 10. A punch-in at 10:15:59 gives the wrong value for any non-UTC timestamp. | Rewritten to take the attendance date and compute the IST shift start. Compares total seconds against 600 (strictly greater), then floors to minutes since shift start (R2). |
| 3 | `compute_work_hours` | Uses Python's `round()`, which is float-based and not half-up. It also does not truncate seconds. | 8.125 hours may come out as 8.12 instead of 8.13. | Uses integer seconds and `Decimal` with `ROUND_HALF_UP` to 2 places (R4). |
| 4 | `compute_overtime` | (a) Subtracts an aware IST time from a naive punch-out, which raises `TypeError`. (b) No 30-minute minimum (R3). (c) Ignores that an overnight shift ends on the next day. | Any punch-out call crashes. Even if it didn't, punching out at 18:59 on a 18:30 shift would give 29 instead of 0. | Rewritten with an aware shift-end helper that adds one day for overnight shifts, floors to minutes, and returns 0 below 30. |
| 5 | (missing) `half_day` calculation | The starter has no helper for R5 and always stores `half_day: False`. | A 3.5-hour day is never flagged as a half day. | Added `compute_half_day(work_hours)`, returning true when the rounded hours are below 4.50. |
| 6 | (missing) attendance date logic | The starter takes the date from `ts.date()` in server-local time. It ignores IST and the overnight-shift rule (R1). | A punch-in at 01:00 IST for a 22:00-06:00 shift gets the wrong date. | Added `attendance_date()`, which converts to IST and subtracts a day when an overnight-shift punch-in is earlier than shift end. |
| 7 | `/health` and `MongoClient` setup | Always returns `ok` without touching MongoDB, and the client has no server-selection timeout. | Stop MongoDB (or use a wrong URI): `/health` still says 200, but the spec requires 503. | Pings the database and returns 503 on failure. Set `serverSelectionTimeoutMS=3000` so it fails fast. |
| 8 | Startup (no indexes) | No indexes are created, so uniqueness is not enforced and every query is a collection scan. | `explain()` shows `COLLSCAN`. Two parallel creates produce duplicate employees. | `lifespan` hook creates a unique `emp_code` index, a `(department, emp_code)` index, and a unique `(emp_code, date)` index. |
| 9 | `create_employee` | Check-then-insert race: two simultaneous requests both pass `find_one` and both insert. | Fire the same POST twice in parallel and get two 201s and duplicate rows. | Removed the pre-check. The unique index decides, and `DuplicateKeyError` becomes 409. |
| 10 | `create_employee` | `datetime.now()` is naive local time, and `created_at` is returned as a datetime instead of epoch milliseconds. | Response `created_at` is an ISO string, not an integer. | Uses `datetime.now(timezone.utc)` and converts with `to_ms()` on output. |
| 11 | `EmployeeIn` | No validation. It accepts a bad `emp_code`, empty name, bad email, impossible dates, or `shift_start == shift_end`. | POST `emp_code: "ABC"` or `joined_on: "2026-02-30"` returns 201 instead of 422. | Added regex and length constraints, a real-date check, and a validator that rejects equal shifts. |
| 12 | `list_employees` | `skip = page * page_size` skips the first page. | `page=1` never returns the first employees. | Changed to `(page - 1) * page_size`. |
| 13 | `list_employees` | `total` counts the whole collection, not the filter. There is no sort, no bounds on `page` and `page_size`, `created_at` is not converted, and an empty `department=` is ignored. | `?department=X` returns the wrong `total`. Page order is unstable. `page_size=100000` is accepted. | Count uses the same filter, sort by `emp_code`, `Query(ge=1, le=100)`, and `employee_out()` converts times. |
| 14 | `punch_in` | Unknown `emp_code` makes `emp` `None`, and `emp["shift_start"]` raises `TypeError`, giving a 500. | POST punch-in with `EMP9999`. | Returns 404 when the employee is not found. |
| 15 | `punch_in` | Timestamp and date use `datetime.fromtimestamp` and `.date()` in server-local time. There is no IST handling, no overnight rule, no second truncation, and `if body.punched_at` treats 0 as missing. | A punch-in at 01:00 IST on a night shift gets the wrong `date`. | Builds a UTC timestamp truncated to seconds, uses `attendance_date()` for the IST/overnight date, and checks `is None`. |
| 16 | `punch_in` | Check-then-insert race: two simultaneous requests both pass `find_one`, so both can insert. | Send two identical requests in parallel and get two 201s. | Removed the pre-check. The unique `(emp_code, date)` index makes exactly one insert win, and `DuplicateKeyError` becomes 409. |
| 17 | `PunchInIn` / `punch_in` | `status` is unvalidated, so `"ABSENT"` or any text is accepted. `punched_at` accepts floats, seconds-sized values or garbage. | POST `status: "banana"` returns 201. | `Literal["PRESENT","WFH","ON_DUTY"]` and `StrictInt` with millisecond bounds, so bad input gives 422. |
| 18 | `punch_in` response | Returns `id` (MongoDB `_id`) and raw datetimes, but the contract says `_id` is never exposed and instants are epoch milliseconds. | Response has `id` and ISO-style datetimes. | `attendance_out()` builds the response explicitly with epoch ms and no `_id`. |
| 19 | `list_attendance` | Loads the whole collection with `list(find(q))`, then sorts and slices in Python. | Slow and memory-hungry with 100k records. | `count_documents` plus `.sort().skip().limit()` inside MongoDB. |
| 20 | `list_attendance` | Sorts by `date` only (no `emp_code` tie-break), has no bounds on `page` and `page_size`, and does not validate dates or `status`. `date_from > date_to` is silently accepted. | Order changes between calls. `?date_from=2026-07-10&date_to=2026-07-01` returns 200 instead of 422. | Sort `date` desc then `emp_code` asc, `Query(ge=1, le=100)`, date validation, a `Literal` status, and compound indexes that match the sort. |
| 21 | `list_attendance` response | Returns `id` and raw datetimes. It does not apply defaults for legacy records that lack `half_day` or `history`. | Legacy record EMP0002 has missing fields, and nested `history` dates would not be milliseconds. | `attendance_out()` and `history_out()` fill defaults and convert every nested instant to epoch ms. |


## Looked at and decided NOT a defect

- **`load_dotenv()` at import time:** by default it does not override environment variables that are already set, so real environment variables win over `.env`. That is the behaviour we want.
- **`IST = timezone(timedelta(hours=5, minutes=30))`:** a fixed offset is correct because India has no daylight saving time, so no timezone database is needed.
- **`doc.pop("_id", None)` after `insert_one`:** `insert_one` adds `_id` to the dict, so removing it before returning is right (the API must never expose `_id`).
